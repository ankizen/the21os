# Self-Hosted AI Ads & Analytics System for The21Secrets — Deep Technical GitHub Research

## Executive Conclusion

A private, self-hosted replacement for Pipeboard's paid Meta Ads MCP is technically feasible and legally permissible for internal business use under current licensing. The optimal path is not to fork Pipeboard directly, due to its Business Source License 1.1 restriction on competing hosted services and its coupling to Pipeboard's cloud OAuth proxy, but to build a unified `THE21SECRETS ADS MCP` server using a production-grade Python FastMCP template as the scaffold, the official `facebook-business` SDK as the Meta transport layer, and the official Google Analytics Data and Admin APIs for GA4, borrowing safety, validation, and modular design patterns from MIT-licensed community servers, most notably `brandu-mos/konquest-meta-ads-mcp` and `bertramdev/MetaAdsMCP` [[1]](https://github.com/pipeboard-co/meta-ads-mcp) [[2]](https://github.com/brandu-mos/konquest-meta-ads-mcp) [[3]](https://github.com/bertramdev/MetaAdsMCP).

The resulting architecture exposes a single MCP endpoint with two internal modules, enforces hard-coded budget ceilings and action quotas at the code layer, defaults all creates to `PAUSED`, and connects to Claude via STDIO for local development and Streamable HTTP with Bearer token authentication for production. The official Meta MCP at `https://mcp.facebook.com/ads`, launched April 29, 2026 with 29 tools and OAuth-based instant access, validates the tool surface area and confirms that no Meta app approval is required for self-use, but its phased rollout and browser-based OAuth make it unsuitable as a headless private backend today [[4]](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started).

## Can I Replace Pipeboard?

Yes. Pipeboard's repository is licensed under Business Source License 1.1, which explicitly permits free use, modification, and redistribution for individual and business purposes, converts to Apache 2.0 on January 1, 2029, and only prohibits offering it as a competing hosted service [[1]](https://github.com/pipeboard-co/meta-ads-mcp). Private internal self-hosted use for The21Secrets falls within the permitted scope. The practical limitation is not legal but architectural: the hosted remote MCP at `https://meta-ads.mcp.pipeboard.co/` holds the OAuth grant and proxies requests, while the open-source code is a reference implementation that expects either a Pipeboard token or a direct Meta access token with `appsecret_proof` support added in PR #35 [[1]](https://github.com/pipeboard-co/meta-ads-mcp).

A complete self-hosted implementation requires:

- A Meta Developer App with Marketing API product, System User token with `ads_read`, `ads_management`, `business_management`, `pages_show_list`, and optionally `catalog_management`.
- Direct use of `facebook-business` SDK v25.0.0, which is the officially maintained Python SDK autogenerated from SDK codegen [[5]](https://github.com/facebook/facebook-python-business-sdk).
- Re-implementation of 30-40 core tools covering accounts, campaigns, ad sets, ads, creatives, image/video upload, insights, and targeting, plus safety enforcement, pagination, rate-limit handling, and audit logging.
- A separate GA4 module using `google-analytics-data` and `google-analytics-admin` Python clients, mirroring the pattern in `googleanalytics/google-analytics-mcp` [[6]](https://github.com/googleanalytics/google-analytics-mcp).

Pipeboard's value proposition of 230+ tools across five platforms behind one auth is unnecessary for a single-business private stack. The cost of rebuilding the Meta-only subset is 3-6 weeks of focused Python development.

## Best Architecture

Architecture E is superior for the stated constraints: private personal/business use, low cost, full control, no Pipeboard dependency, easy maintenance, security, Claude compatibility, future expansion, campaign creation, creative management, optimization, analytics, and debugging.

```
                    CLAUDE
                       ↓
             THE21SECRETS ADS MCP
          (FastMCP Python, STDIO + Streamable HTTP)
                       ↓
          ┌────────────┴────────────┐
          ↓                         ↓
     META MODULE                GA4 MODULE
   facebook-business SDK   google-analytics-data / admin
          ↓                         ↓
   Meta Marketing API        Google Analytics API
          ↓
   Safety Layer / Budget Guardrails / Audit Log / SQLite
```

## Claude Integration

Claude supports local MCP via STDIO and remote via Streamable HTTP. Official Meta MCP at https://mcp.facebook.com/ads is HTTP with OAuth, added via claude mcp add --transport http --client-id <META_APP_ID> meta-ads https://mcp.facebook.com/ads [[4]](https://developers.facebook.com/documentation/ads-commerce/ads-ai-connectors/ads-mcp-server/ads-mcp-server-get-started). Pipeboard remote via https://meta-ads.mcp.pipeboard.co/ with token param [[1]](https://github.com/pipeboard-co/meta-ads-mcp).

Production private method:

- Local dev: STDIO config in .mcp.json with command uv --directory /path run python -m the21secrets_ads_mcp, env vars for tokens.
- Production: Streamable HTTP Docker exposing 0.0.0.0:8000/mcp, Bearer token auth, TLS via Caddy, token in env.
- Tool schema: Pydantic models, JSON Schema, annotations readOnlyHint, destructiveHint, idempotentHint, openWorldHint. Keep tool count <40 to avoid context overflow; if more, implement semantic search tool filtering.
- Claude Code requires explicit allow rules in settings.json, annotations don't auto-approve.

## Authentication Architecture

```
Claude (STDIO) → env META_ACCESS_TOKEN (System User, non-expiring)
              → META_APP_ID + META_APP_SECRET → appsecret_proof HMAC-SHA256 per request
Claude (HTTP) → Bearer <PRIVATE_TOKEN> → MCP server → same + Google SA key
GA4 → GOOGLE_APPLICATION_CREDENTIALS JSON path → Service Account Viewer
    → GA4_PROPERTY_ID env
```

Flow: Create Meta App Business type → Add Marketing API → Business Manager System Users → Create System User → Assign ad accounts → Generate token ads_read, ads_management, business_management, pages_show_list, instagram_basic → Store encrypted .env → MCP server loads via dotenv, validates, computes appsecret_proof, loads GA4 credentials via google-auth → Safety layer checks budget ceilings before writes.

## Security and Budget Guardrails

Requirement: Claude never bypasses rules. Enforce at code layer.

Pattern from konquest and bertramdev:

- config.py env: MAX_DAILY_SPEND=₹1500 (minor units), MAX_BUDGET_INCREASE_PCT=20, MAX_NEW_CAMPAIGNS_PER_DAY=2, MAX_ADS_PER_CAMPAIGN=10, REQUIRE_APPROVAL_OVER=500, DRY_RUN_DEFAULT=true, READ_ONLY_MODE=false, AUDIT_LOG_PATH=./logs/audit.jsonl
- safety module: rate_limiter parsing x-business-use-case-usage, budget_enforcer, quota_tracker SQLite, audit_log
- Every write tool calls check_safety before API:
  - If READ_ONLY_MODE → reject
  - If DRY_RUN → validate, return preview
  - If daily spend > MAX_DAILY_SPEND → reject
  - If budget increase > MAX_BUDGET_INCREASE_PCT → require approval
  - If campaigns today >= MAX_NEW_CAMPAIGNS_PER_DAY → reject
  - If ads per campaign >= MAX_ADS_PER_CAMPAIGN → reject
- All creates default PAUSED, no ACTIVE without confirm_active=True + audit log
- Audit logs JSONL with timestamp, actor, tool, params, before/after
- Rollback via previous value journal, tool rollback_action
- Secret redaction in logger
